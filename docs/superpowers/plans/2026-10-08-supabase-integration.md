# Supabase Full-Stack Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate Flo Studios' data architecture from local storage to Supabase (PostgreSQL tables with strict RLS, private resume storage with signed URLs, email/password Supabase Auth, and CMS management).

**Architecture:** A unified service layer in `src/services/supabaseService.js` and client in `src/lib/supabase.js` that talks directly to Supabase cloud. Public endpoints safely insert inquiries and applications under anonymous RLS permissions, while the `/admin` portal authenticates via Supabase Auth to read, update, star, or delete records and generate signed resume preview URLs.

**Architecture Diagram:**

```mermaid
graph TD
    subgraph "Frontend Layer"
        CF[Contact Form / Modal] --> AS[adminStorage Unified Gateway]
        CP[Careers Page & Resume Upload] --> AS
        AP[Admin Portal /admin] --> AS
    end

    subgraph "Supabase Service Layer"
        AS --> SS[supabaseService.js]
        SS --> SC[supabase.js Client]
    end

    subgraph "Supabase Cloud"
        SC --> AUTH[Supabase Auth (Admin JWT)]
        SC --> DB[(PostgreSQL Database + RLS)]
        SC --> ST[(Private Storage: resumes)]
    end
```

**Tech Stack:**
- `@supabase/supabase-js` (Client SDK)
- PostgreSQL 15+ (Supabase Database)
- Supabase Storage (Private S3-compatible bucket)
- Supabase Auth (GoTrue email/password)
- React 19 + Vite

## Global Constraints
- Strictly follow `supabase-postgres-best-practices`: enable RLS on all tables, avoid deprecated `auth.role()`, use `TO anon` and `TO authenticated`.
- Zero broken builds: `npm run build` must succeed after every task.
- Resilient hybrid fallback: When `.env` credentials are not yet populated, the site must display informative setup notices and gracefully fall back to local storage without crashing.
- Private resume protection: Candidate CVs stored in a private bucket, accessible only via signed URLs generated by authenticated admin sessions.
